# Issue Workflow

## Why

Issue defines problem and acceptance boundary. It should not prescribe
implementation before investigation.

## Ready Criteria

- Clear problem statement and user/system impact
- Acceptance criteria
- Known constraints
- Explicit non-goals when scope may expand
- Dependencies or blockers

## Template

```markdown
## Problem

## Impact

## Acceptance Criteria
- [ ]

## Constraints

## Non-goals

## Validation Notes
```

## Lifecycle

Create or refine issue, confirm dependencies, link branch/plan/PR, record scope
changes, and close only after acceptance criteria and required validation pass.
Split independently releasable outcomes; keep tightly coupled steps together.
